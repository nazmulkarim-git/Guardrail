Developers

A small integration point, not a new workflow system.

Start in shadow mode, measure what would need approval, then switch selected checkpoints to active review.

import { Forsig } from "@forsig/sdk";

const forsig = new Forsig({ apiKey: process.env.FORSIG_API_KEY });

const decision = await forsig.escalate({
  mode: "shadow",
  agent: "refund-agent",
  task: "Approve refund for customer #123",
  risk: { type: "refund_over_limit", level: "high" },
  proposedAction: "Issue a $500 refund",
  waitForDecision: true
});

if (decision.status === "approved") {
  await issueRefund();
}

Compliance & trust

Forsig stores decisions, not secrets.

What Forsig stores

  • User or reviewer ID
  • Tool and agent names
  • Action description and risk reason
  • Decision, timestamp, and audit trail

What Forsig never needs

  • API keys, passwords, or private tokens
  • Full payment records
  • Unnecessary customer data
  • Private agent memory

FAQ

Common beta questions.

How quickly can I test Forsig?

You can create an API key, run the quickstart script, and approve your first test escalation in minutes.

Does Forsig block my agent forever?

No. You set timeouts and fallback behavior. Risky actions can fail closed when nobody responds.

Can I use Forsig without sending sensitive data?

Yes. Send only the action, risk reason, and minimal context a reviewer needs.

Is this production-ready?

Forsig is in private beta. Start with shadow mode, then enable active approvals for selected low-blast-radius workflows.
