How it works

Intervention in four steps.

01

Agent reaches risk

Refund, email, CRM update, tool action, policy exception, or missing context.

02

Forsig creates review

Your app sends the proposed action, context, risk type, and run ID.

03

Human decides

Approve, reject, edit, instruct the agent, or take over the task.

04

Agent resumes

Forsig returns structured data your workflow can use immediately.

Why teams need it

Agents do not always need autonomy. They need a safe way to ask.

Review inbox

One place for pending interventions across agents, workflows, and reviewers.

In-place edits

Humans can correct the next action instead of only saying yes or no.

Webhook-ready decisions

Return a status, instruction, edited action, and audit ID to your app.

Audit trail

Know what the agent wanted, who reviewed it, and what happened next.

Developer flow

One call when the agent needs judgment.

Illustrative SDK example
const decision = await forsig.intervene({
  agent: "refund-agent",
  runId: "run_123",
  risk: "refund_over_limit",
  proposedAction: "Issue $500 refund",
  waitForDecision: true
});

if (decision.status === "edited_approved") {
  await continueWorkflow(decision.editedAction);
}

What is Forsig?

Forsig is a human intervention API for AI agents. It lets agents pause before risky actions and return a structured human decision.

How is Forsig different?

Forsig is focused on intervention checkpoints for agent workflows, not a model gateway, observability dashboard, or support inbox.

What can a human do?

Approve, reject, edit and approve, instruct the agent, or take over the task.

Is it production-ready?

Forsig is in private beta. Early users should expect setup help and fast iteration.
